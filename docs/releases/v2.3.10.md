# v2.3.10 发布说明

日期：2026-10-05。

本轮修正原生导线读取格式及四个消费者的几何解释，定向回归、typecheck、目标 lint、两轮独立审查及两包完整本地门禁已通过；2.3.10 最终宿主只读 preview 尚待验证。实际发布状态以 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases/tag/v2.3.10) 和关联 PR 为准。Bridge 与 Server 应安装相同版本。

## 原生线段与连续写请求

EDA 3.2.181 / API 0.3.15 捕获的 3 个完整 Wire DTO 与 15 条源码记录（3 WIRE、12 LINE）一一对应，证明本次原生 `Wire.line` 按 `[x1,y1,x2,y2]` 独立端点对存放线段。源码 Y 坐标与 SDK 读取方向相反，fixture 按此映射核对每条实际 LINE。

旧读取逻辑每 2 个坐标前进，错误地把前一线段终点和后一线段起点相连，产生不存在的斜线。新共享解析器每 4 个坐标读取一个独立线段；不会在两组端点对之间补线，也不改写真实 DTO 的原始顺序或 `line`。

例如原生读取 `[0,0,10,0,20,10,20,20]` 表示两条独立线段 `(0,0)→(10,0)` 和 `(20,10)→(20,20)`，不存在 `(10,0)→(20,10)`。

创建/修改参数仍遵守官方连续路径语义，例如 `[800,100,900,100,900,200]` 是连续 L 请求；raw 创建的五参数与多路径能力不变。请求路径和实际读取分别解释后再核对，不能把连续请求每 4 个坐标切断，也不能把原生读取当作连续折线。

## 四个消费者同步

- `schematic_connectivity_action`：接触预检及创建覆盖使用实际线段，虚构斜线不再导致异网误拒；真实异网接触仍拒绝。
- `schematic_read`：语义图仅按实际线段连接端点、线中引脚及端口，修正读取时错误网络传播；完整连接快照保留原生 DTO。
- `schematic_wire_manage`：net-only 修改逐实际线段检查，仅向原生传网络属性而不重写几何；几何修改将实际独立线段和连续请求分别归一，接受同形线段拆分、反向和重排，真实 `after.line` 保留。
- `schematic_component_edit`：匿名导线组使用相同解析器，器件移动不再把虚构斜线当作原有匿名连接，真实线段上的组变化仍按既有规则核对。

本轮没有新增工具或改变网络名、ID、位号及 BOM 的写入规则，也不提供宿主网络合并回滚。

## 本轮验证范围
