# v2.3.8 发布说明

日期：2026-10-05。

本地完整构建、回归、独立审查及下列共享封装源保存实机验证已完成；实际发布状态以 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases/tag/v2.3.8) 及关联 PR 为准。Bridge 与 Server 应安装相同版本。本轮按“区分内存删除与保存，并支持共享封装源持久编辑”的范围收口 #80，不将板级子过孔删除本身声明为通用持久删除。

## 保存当前共享封装源

新增 `footprint_save`，路由为 `/bridge/jlceda/footprint/save`。工具仅接受可选 `timeoutMs`，范围 5000–120000 毫秒，默认 30000；不接受源码、目标 UUID 或图元过滤参数，保存当前独立封装文档。

```json
{
  "timeoutMs": 30000
}
```

Bridge 读取当前封装的真实库、文档与标签身份，调用一次 `sys_FileManager.getDocumentSource()` 获取读取时包含当前编辑的完整源码快照。在最后一次身份读取后核对连接、活动角色与租约，再调用一次 `lib_Footprint.updateDocumentSource(documentUuid, libraryUuid, source)`。源码原样在 EDA 内写回，不传回 MCP 客户端；保存不额外执行七类 `getAll`。库身份沿用匹配当前文档的实际 canonical 标签规则，不用 PCB 或工程缓存代替。官方接口未提供 revision/CAS，不保证与同页人工并发编辑之间的原子保存；本轮不增加重复源码读取。

该操作更新共享库源，可能影响所有引用该封装的实例。工具不自动关闭页面、重建器件或将某个 PCB 实例重绑定到私有副本；需要仅此实例修改时，本轮没有对应能力。

## ACK、失败与未知结果

保存响应包含真实身份、`scope:"library_source"`、`sharedSource:true` 和 `sourceLength`（源码字符串长度）。

| 结果 | 返回语义 | 后续处理 |
| --- | --- | --- |
| 库 API 返回 true，后续身份仍一致 | `ok:true`、`saved:true`、`saveAcknowledged:true`、`identityVerified:true`、`nativeCallSettled:true` | 保存 ACK 已确认；持久状态需要另外关闭重开封装和引用 PCB 后完整回读 |
| true ACK 后换页或身份读取失败 | `ok:false`，仍为 `saved:true`、`saveAcknowledged:true`；`identityVerified:false`、`reason:"footprint_changed_after_save"` | ACK 仍成立，不直接重试已保存的写入；核对当前页面和目标状态 |
| 库 API 明确返回 false | `ok:false`、`saved:false`、`saveAcknowledged:false`、`nativeCallSettled:true`、`reason:"native_footprint_save_not_acknowledged"` | 只确认未获 ACK，不据此声称源码未改变 |
| 库 API 返回 undefined | `ok:false`、`commitUnknown:true`、`readbackRequired:true`、`nativeCallSettled:true`、`reason:"native_footprint_save_unknown"`，不带 `saved` 或 `saveAcknowledged` | 已结束但效果未知；不强制宿主重启，须同库同文档完整回读恢复 |
| 原生 RPC 未确认或执行超时 | `commitUnknown:true`、`readbackRequired:true`、`nativeCallSettled:false`，不补 `saved:true` | 按诊断建立恢复会话，原生调用可能未结束时先重启原 EDA 宿主，再完成同库同文档的完整回读 |

写前源码缺失、文档不匹配或租约失效时停止尚未开始的库写入。已结束的明确原生错误返回失败诊断；它不等于失联，也不能证明源码没有变化。库 ACK 只表示 `updateDocumentSource` 已返回 true，不能独立证明所有引用 PCB 的保存与冷重开状态。

## 未知保存的受控恢复

`footprint_save` 的未知提交使用 `requiredReadback:"footprint_state"`：

1. 从 `bridge_clients` 取得诊断 `requestId`，执行 `bridge_recover_client action:"recover"`、`confirm:true`。
2. 诊断要求宿主重启时，重启原 EDA，打开任务执行时同库同封装文档。
3. 使用恢复会话后的新客户端执行 `action:"readback"`，提供 `recoveryId`、`clientId`、`confirm:true`、`readbackPath:"/bridge/jlceda/footprint/read"`、`readbackPayload:{}`；按诊断提供 `hostRestartConfirmed:true`。
4. Server 核对执行时库/文档身份及七类完整 DTO；新标签可不同于旧任务，但一次回读期间库、文档与标签必须稳定。仅查询上下文、局部图元或错误库不能解除隔离。

`readbackVerified:true` 与解除写入隔离只证明当前完整编辑状态，不补发保存 ACK，也不声称 `saved` 或引用 PCB 已持久保存。原生调用尚未结束时，即时快照不能作为重试依据。

## 本轮实机验证

环境为 EDA 3.2.181、宿主 API 0.3.15、Server 2.3.8 与活动 Bridge 2.3.8。使用独立自建工程库封装及其引用 PCB，不修改原工程库源；仅记录本轮自建夹具。初次打开标签后两次只读返回页面尚未就绪，未执行写入；等待 `footprint_read complete:true` 后才进行创建和保存。

| 阶段 | 冷重开封装 | 冷重开引用 PCB | 完整状态核对 |
| --- | --- | --- | --- |
| 初始基线 | 4 个图元，Via 0 | 1 个器件、3 个 Pad，Via 0 | 保存本轮完整基线 |
| 独立封装创建 Via 后调用 `footprint_save` | 5 个图元，Via 1；库 ACK true，源码长度 28511 字符 | Via 1 | 封装全部 DTO 与创建后严格相等；PCB 除 vias/viaCount 外所有读取部分与基线相等 |
| 删除该封装 Via 后再次调用 `footprint_save` | 4 个图元，Via 0；库 ACK true，源码长度 28241 字符 | Via 0 | 封装完整状态及 PCB 全部读取部分均严格恢复原基线 |

两次保存均返回 `saved:true`、`saveAcknowledged:true`、`identityVerified:true`、`nativeCallSettled:true`、`scope:"library_source"`、`sharedSource:true`。这证明本轮共享库源编辑路径的 Via 0→1→0 及冷重开状态，不证明任意 PCB 内存删除都会持久，也不扩大为仅修改一个引用实例。

本机标准 MCP 脚本 `jlc-238-save-created-native.mjs`、`jlc-238-save-delete-native.mjs` 均通过；证据摘要为 `jlc-238-save-native-proof.json`，原始 ACK 为 `jlc-238-save-created-ack.json`、`jlc-238-save-delete-ack.json`。undefined 返回、保存 RPC 失联或 ACK 后身份读取失败仅由本地回归验证，本轮没有对应实机异常测试。前代手动写源验证保留在 [2.3.7 发布说明](v2.3.7.md)，不作为新工具实机证据。

## 自动门禁与保留限制

本轮最终本地门禁全部通过：

- Bridge：完整 `npm run build`，含保存处理器/runtime 回归、typecheck、API 文档/runtime 验证及扩展打包；`npm run lint`。
- Server：全量 `npm test`、`npm run lint`、`node verify-multi-client.mjs`，含实际 SDK 工具入口、分发以及主连接/中继恢复回归。
- 针对保存 ACK 后身份失败、false 未 ACK、undefined 已结束但效果未知、RPC 未确认、写前身份与租约变化，以及错误库/不完整恢复快照的本地回归通过；保存过程不额外调用七类图元读取的断言通过。

远端 CI 与关联 PR 审查按发布流程核对。本轮没有取消宿主 RPC、通用 PCB 子图元持久删除、自动器件重建或仅此实例封装重绑定能力；#80 收口范围为诚实区分内存与持久状态，并提供已实测的共享源保存流程。#22 原 TPS552892 布局和宿主根因仍缺原场景 fixture，PCB 自动布线 #37 沿用既有验证限制，EDA v4 未实机验证。
