# v2.3.5 发布说明

日期：2026-10-05。状态：已通过发布验证。MCP Server 与 EDA Bridge 的目标版本均为 2.3.5。

两轮本地全面审查、Server/Bridge 全量构建测试及 lint 已通过；2.3.5 已安装；最终补修通过热更新实测，运行版本一致。原理图和 PCB 已测场景如下，过孔创建/修改、工程库来源核对、覆铜等价轮廓创建/修改及真实 DRC 28 条详情的 14 页连续读取均已实测通过。各 Issue 的证据与保留状态见 [Issue 验证记录](../issue-validation-2.3.5.md)。

## 器件与原理图操作

- 器件裸引用先经设备库查验，解析为完整 DeviceItem 后再创建；查无设备时立即返回 `DEVICE_NOT_FOUND`，避免进入可能挂起的原生创建。
- 支持唯一子件名称的自动解析。2.3.5 实机连续放置 C23221、C96346、C84376、C110775 的 4 型号批次全部成功，合计约 8.9 秒。
- ComponentPin 的 NC/引脚号修改使用真实器件引脚实例。实机同一引脚 NC `true`→`false` 两次均验证成功，坐标与同器件其他引脚保持不变。
- ComponentPin 失败恢复要求 `schematic_read includeConnectivityPrimitives:true`，以包含引脚 ID、坐标、旋转和 NC 的语义快照核对所属器件全部引脚。
- 设备名称属性搜索核对实际名称，各页固定使用关键词搜索并核对全部请求属性；最终扩展实机按 limit:1 连续查询两页：第一页返回 1 条精确匹配，第二页为空且 mayHaveMore:false，两页均为 keyword_name_filter。
- NetPort Name 读取改用父图元属性与按 ID 查询；最终实机类型查询、单件和批量读取均返回 Attribute，保留一致的真实父 ID、Name 值和坐标。
- 制造导出仅计算选定 domain/kind 的参数，BOM、文档、标准与仿真网表各自校验格式。实机原理图 BOM CSV（740 B）、JLCEDA 网表（18,883 B）、PDF（35,886 B）和 PCB BOM CSV（334 B）均生成成功。
- 点导线转换为多线段路径在写入前明确拒绝，可新建目标导线并核对连接后再显式删除原点导线。

## PCB 回读与诊断

以下改动已有本地回归和交叉审查；实机结果与尚未解决的问题分别注明。

- 器件旋转按模 360 度比较，实机请求 `-90`、回读 `270` 已验证；`supplierId` 与 `otherProperty` 修改及实际回读通过。部分修改失败返回实际状态与字段差异。
- 闭合板框与区域支持等价方向、起点和已观察的四位小数坐标回读；开放板框路径只接受完整反向。实机板框反向、显式闭合区域反向与四位小数回读已验证。
- 直线创建核对原生拆分/合并后的共线覆盖，实机返回 2 个实际 ID 并验证覆盖。过孔创建与尺寸修改只接受精确尺寸或实测 0.2 mil 最近格点（`round_0_2_mil`），返回请求与实际尺寸；创建和修改已实测通过，返回实际尺寸与 round_0_2_mil。
- 原生创建将设备或封装复制进工程库时，以创建返回来源与请求来源或同 ID 回读的一致性确认，并返回 `normalization.source`；实机创建与工程库来源回读已验证。
- 覆铜重建增加逐实例回退，缺失 API 时返回明确能力诊断。实机全板重建回读 1 个边框和 1 个填充，验证成功；创建/修改增加闭合轮廓等价比较，实机等价反向与四位小数轮廓创建、修改已验证；原生重排已有覆铜优先级仍按实际 sideEffects 报告。
- PCB 属性文字的 `value`、`valueVisible` 可通过 Server 输入校验，实机两字段修改与实际回读已验证。
- PCB DRC 提供详情分页，区分原生未返回详情与 Bridge 深度/大小截断，并保留正确续页位置。 实机含 28 条错误的 PCB 按 limit:2 连续读取 14 页，数量、nextOffset 和直线端点完整，两种截断标志均 false。
- 已知封装子过孔拒绝直接删除；其他过孔删除明确仅确认当前页内存消失，保存重开后的持久性仍未验证。
- 非字符串错误在 Bridge、主连接、中继及分发中保留安全诊断字段。

## 发布审查补修

名称属性查询的所有页固定使用关键词搜索，并在本地核对全部请求属性，返回 `searchImplementation:"keyword_name_filter"`；`mayHaveMore` 仍依据原生候选页，避免每页切换搜索后端。裸器件引用明确指定库时，同时核对返回记录的器件 UUID 与库 UUID，不一致则在创建前返回 `DEVICE_LOOKUP_MISMATCH`。 这两项补修均通过两轮本地复查、定向回归和最终构建；热更新后名称分页实测通过，指定系统库的 C23221 正常放置 1 件，未进入写入隔离。错误来源库分支在调用原生创建前拒绝的行为由本地回归确认。

发布审查补修：普通 Pin 与 ComponentPin 按实际执行路径区分超时恢复；ComponentPin 仍要求所属器件全部引脚的完整回读。直线拆分/合并核验记录同网络、同层写前快照，要求本次新增或改变的有效线路，并返回 `changedPrimitiveIds`。过孔修改核对实际外径大于孔径，量化后的零环宽返回实际状态与差异。

三项审查补修均已完成两轮本地复查。最终 Bridge 完整构建、两包全部测试入口、lint 与多客户端协议验证通过。最终扩展热更新后，再次实测 ComponentPin 的 NC true→false，完整原理图语义快照恢复一致；直线拆分/合并返回 2 个本次变化的实际 ID 与 `changedPrimitiveIds`；正常过孔量化修改仍 verified:true。普通 Pin / ComponentPin 的真实无结果超时、迟到分类和中继恢复，以及零环宽失败分支由针对性本地回归验证。

## 安装与兼容

发布后从同一个 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases) 安装 `jlceda-mcp-server-2.3.5.tgz` 和 `mcp-bridge-community-2.3.5.eext`，并启用扩展“外部交互”权限。运行环境需要 Node.js 20 或更高版本。

扩展声明兼容嘉立创 EDA 专业版 3.x，现场使用 3.2.181。普通网络标签仍依赖 EDA v4 的 `createNetLabel`；本版不声明 EDA v4 支持。2.3.4 的 `board_setup` 创建与关联工作流保持可用，历史说明见 [v2.3.4](v2.3.4.md)。

详细变更见 [Bridge 更新日志](../../mcp-bridge/CHANGELOG.md)与 [Server 更新日志](../../mcp-server/CHANGELOG.md)。社区版并非嘉立创官方插件。
