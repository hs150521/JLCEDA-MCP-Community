# v2.3.5 发布说明草稿

日期：2026-10-04。状态：待发布，实机验证仍在进行。MCP Server 与 EDA Bridge 的目标版本均为 2.3.5。

两轮本地全面审查、Server/Bridge 全量构建测试及 lint 已通过；2.3.5 已安装并重启，运行版本一致。已完成部分原理图实测，NetPort 属性读取修正及 PCB 验证尚待完成。本说明不会将全部 23 个 Issue 记为已解决；完整证据见 [Issue 验证记录](../issue-validation-2.3.5.md)。

## 器件与原理图操作

- 器件裸引用先经设备库查验，解析为完整 DeviceItem 后再创建；查无设备时立即返回 `DEVICE_NOT_FOUND`，避免进入可能挂起的原生创建。
- 支持唯一子件名称的自动解析。2.3.5 实机连续放置 C23221、C96346、C84376、C110775 的 4 型号批次全部成功，合计约 8.9 秒。
- ComponentPin 的 NC/引脚号修改使用真实器件引脚实例。实机同一引脚 NC `true`→`false` 两次均验证成功，坐标与同器件其他引脚保持不变。
- ComponentPin 失败恢复要求 `schematic_read includeConnectivityPrimitives:true`，以包含引脚 ID、坐标、旋转和 NC 的语义快照核对所属器件全部引脚。
- 设备名称属性搜索核对实际名称，必要时回退到关键词再过滤；实机精确名称查询返回 1 条匹配记录，排除 20 条无关记录。
- 制造导出仅计算选定 domain/kind 的参数，BOM、文档、标准与仿真网表各自校验格式。实机原理图 BOM CSV、JLCEDA 网表和 PDF 均生成成功。
- 点导线转换为多线段路径在写入前明确拒绝，可新建目标导线并核对连接后再显式删除原点导线。

## PCB 回读与诊断

以下改动已有本地回归和交叉审查，实机 PCB 验证尚未完成。

- 器件旋转按模 360 度比较；元数据部分修改失败返回实际状态与字段差异。
- 闭合板框与区域支持等价方向、起点和已观察的四位小数坐标回读；开放板框路径只接受完整反向。
- 直线创建核对原生拆分/合并后的共线覆盖；过孔创建返回已知 0.1 mil 网格归一化的实际尺寸和规则。
- 覆铜重建增加逐实例回退，缺失 API 时返回明确能力诊断。
- PCB 属性文字的 `value`、`valueVisible` 可通过 Server 输入校验。
- PCB DRC 提供详情分页，区分原生未返回详情与 Bridge 深度/大小截断，并保留正确续页位置。
- 已知封装子过孔拒绝直接删除；其他过孔删除明确仅确认当前页内存消失，保存重开后的持久性仍未验证。
- 非字符串错误在 Bridge、主连接、中继及分发中保留安全诊断字段。

## 尚未完成的验证与限制

- NetPort 的 Name 属性首次新版实测仍返回 Text；父图元属性查询路径正在修正，需最终实机确认。
- 新 PCB 的原生 `openDocument` 出现悬挂及黑屏，正在重启恢复后继续验证 PCB 工具。
- 过孔修改请求 `15.7` 回读 `15.8` 的偏差尚未解决；创建的归一化规则不会放宽修改校验。
- 封装子过孔保存后再生与独立封装编辑器 Bridge 上下文继续开放。
- #22/#26/#30/#34/#37 的旧原场景或原生限制继续保留，不能仅凭本轮其他场景通过而关闭。

## 安装与兼容

发布后从同一个 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases) 安装 `jlceda-mcp-server-2.3.5.tgz` 和 `mcp-bridge-community-2.3.5.eext`，并启用扩展“外部交互”权限。运行环境需要 Node.js 20 或更高版本。

扩展声明兼容嘉立创 EDA 专业版 3.x，现场使用 3.2.181。普通网络标签仍依赖 EDA v4 的 `createNetLabel`；本版不声明 EDA v4 支持。2.3.4 的 `board_setup` 创建与关联工作流保持可用，历史说明见 [v2.3.4](v2.3.4.md)。

详细变更见 [Bridge 更新日志](../../mcp-bridge/CHANGELOG.md)与 [Server 更新日志](../../mcp-server/CHANGELOG.md)。社区版并非嘉立创官方插件。
