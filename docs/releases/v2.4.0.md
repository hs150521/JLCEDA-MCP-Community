# v2.4.0 发布说明

日期：2026-10-28。

匹配的 Bridge/Server 2.4.0 已在 EDA 4.1.78 完成器件编辑、导出、布线、公共库分类和覆铜重建的 MCP 实机验证；最后一轮分类与覆铜摘要修复已复测通过。两端完整本地自动门禁通过，此处记录本地验证；远端检查与下载状态以 GitHub Actions/Release 为准。

本轮复查并补修 [PR #97](https://github.com/hs150521/JLCEDA-MCP-Community/pull/97)，同步 EDA v4 的 MCP 契约、扩展能力和官方 API 索引。可下载状态以 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases/tag/v2.4.0) 为准。

## PR #97 与实机反馈补修

- PCB 直线修改按请求路径、受影响旧铜和当前页完整回读核验，支持拆线、合并、幂等写入及合并到未变化的已有线段。延伸时允许原 ID 保留为请求路径的一部分，但须证明写前未完整覆盖请求、写后新增覆盖完成；已有重叠铜不能掩盖实际未执行的修改。
- 覆铜重建以当前页回读为权威。原生返回部分、空集合、未变化时的 null，或同一填充的相同重复记录，不单独判定失败；重复数量和 ID 保留为诊断。每条原生记录仍须与实际回读一致，页面回读中的重复 ID、丢失填充或不一致内容仍被拒绝。
- 封装源导出在原生清单缺项、截断，或引用 API/getter 缺失、异常、数据不合法时不再声明 `complete:true`；保留可用源码及已经识别的缺失引用。
- 原理图器件编辑拦截 otherProperty 中的原生绑定及供应商、制造商别名，并核对 Component、Symbol、Footprint 三类库绑定及未请求修改的 BOM 字段。意外清空、绑定改变或失去可读性时返回实际状态和差异。

## EDA v4 与新增功能

官方类型固定到 `@jlceda/pro-api-types 0.4.27`，离线索引同步备注、弃用信息和最低宿主版本；扩展 engines 为 `^3.0.0 || ^4.0.0`。已知版本不满足门槛时，在原生调用前返回 `EDA_VERSION_UNSUPPORTED`、`commitStatus:"not_started"`、`nativeCallAttempted:false`。类型包包含较新接口不代表当前宿主支持，4.1.79、4.2 和 v5 新增方法均依各自元数据检查。

| 功能 | 输入与行为 | 最低宿主版本 |
| --- | --- | --- |
| 原理图 PNG/SVG | `manufacture_export domain:"schematic" kind:"png"/"svg"`；PNG 可选 resolution，每边为 1–4096 整数且至少指定一边；多图页可返回 ZIP | 3.2.183 / 4.1.23 |
| 当前原理图归档 | `design_archive_export action:"schematic"`，沿用归档类型、文件名及受限 Base64 返回 | 3.2.183 / 4.1.23 |
| 原理图/PCB 比较 | 原理图来源仅接受 UUID 字符串；PCB 可选 valUnit、deviation、comparisonSize，后两者须为有限且严格大于零的数；按原生 success 判断成功 | 3.2.205 / 4.1.62 |
| 库分类树 | 优先新 getClassificationTree；方法缺失，或新版合法空树而旧树非空时回退。返回 classificationApi、回退原因及完整 namePath；新版异常或非法结果不回退 | 按方法能力检测 |

旧 `manufacture_export kind:"document"` 继续兼容，其原生接口自 EDA v4.1 起弃用；PNG/SVG 推荐使用对应的新分支。版本未知或缺少元数据时仍需检查原生能力和实际返回。

## 实机验证

所有写入均限制在用户专门建立的 MCP 测试项目中，测试对象为新建 PCB 副本和原理图页副本；未直接修改其他项目。记录不包含私有图纸名称、UUID 或具体器件信息。

| 场景 | EDA 4.1.78 实际结果 |
| --- | --- |
| PCB 线宽修改 | 原值 10 的幂等写入、改为 11、恢复 10 均返回 verified:true |
| 原理图器件改名及恢复 | 两次修改/恢复通过，制造商、供应商、BOM 属性和三类库绑定均保留 |
| 新导出 | PNG width:800、SVG 均返回 ZIP，原理图归档返回 epro |
| 公共库分类 | 新版空树回退旧接口，classificationApi:getAllClassificationTree、fallbackReason:modern_tree_empty；total:8654、returned:5，所返节点 namePath 完整 |
| 覆铜重建 | 原生返回 17 个、页面回读 17 个填充，verified:true、verificationScope:page_readback，不再误入隔离 |
| PCB 比较 | 正数参数返回 success:true；零值实机返回官方 INVALID_PARAM，随后在 schema 与 handler 加入严格正数校验 |
| 原理图比较 | 两个不同原理图 UUID 返回 success:true |
| 版本门槛 | 4.1.78 调用要求 4.1.79 的 waitForReady，返回 nativeCallAttempted:false |
| 封装源完整性 | 有器件 PCB 的官方封装源列表为空时，返回 complete:false，符合预期 |

分类和覆铜使用最后代码的同版 2.4.0 复测；器件、导出及线宽场景在仅上述两项补修前的同版构建完成。比较、版本门槛和空源码行为由本轮较早的宿主验证确认，恢复流程也已完成 recover/readback 验证。

## 自动门禁与发布边界

Bridge 完整 build（含测试）/lint、Server 完整 build/test/lint 与多客户端验证均已通过。末轮分类和覆铜摘要补修后，相关定向测试、lint、typecheck、compile 及 runtime 验证再次通过。

Server 生产依赖审计为 0 项告警；开发依赖审计仍有 Bridge 18 项、Server 9 项告警，本轮未清理。本轮未重跑 EDA 3.x，也未逐项实测 0.4.27 索引中的全部 API。

合并前须通过远端 CI；远端检查与下载状态以 GitHub Actions/Release 为准。GitHub Release 工作流固定触发时的提交，核对版本并重新执行测试构建；手动运行可在全部门禁通过后创建缺失的版本标签。随后上传草稿，再下载校验附件后公开发布，不发布到 npm registry。最终 `.eext`、Server `.tgz` 的 SHA-256 随 Release 的 `SHA256SUMS` 附件提供。

安装时使用同一 Release 中的 `jlceda-mcp-server-2.4.0.tgz` 与 `mcp-bridge-community-2.4.0.eext`，Node.js 要求 20 或更高版本。历史自动布线故障、未提供原夹具的旧 Issue 和共享封装持久性限制，不因本轮适配自动视为解决。
