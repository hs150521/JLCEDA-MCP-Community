# v2.3.6 发布说明

日期：2026-10-05（本地 UTC+08:00）。版本：MCP Server 与 EDA Bridge 2.3.6。本地构建、回归、独立审查与下列实机验证已完成；实际发布状态以 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases/tag/v2.3.6) 及关联 PR 为准。

## 独立封装文档与连接

以官方 `getCurrentDocumentInfo()` 的 `documentType:4`、`uuid`、`parentLibraryUuid`、`tabId` 建立封装身份，返回 `pageKind:"footprint"`、`documentUuid/pageUuid`、`libraryUuid`、`tabId`。封装不要求工程 UUID，也不读取旧 PCB/工程缓存作为身份。Bridge 可在独立封装文档连接，`eda_context.footprintContext` 与 `bridge_clients` 显示真实库文档；PCB/原理图专用工具在此文档中明确拒绝。

独立封装中的 MCP Bridge 菜单已实机可见；菜单重启后新客户端进入 ready，公开选择客户端并完整回读仍为 count:5、身份正确。握手后发送就绪报告失败时，Bridge 清理本次连接并重新尝试，旧连接回调不会清理新连接；该失败分支已通过本地回归，未单独宣称实机故障复现通过。

## 完整读取与首批画布 API

`footprint_read` 一次读取 Pad、Via、Line、Arc、Polyline、String、Attribute 七类，每类全 ID 清单必须与真实 DTO 一一对应；返回不截断数组、各类数量和 `primitiveCount`。Pad 包含形状、孔、孔偏移/旋转及 padType；Polyline 保留原生 source 数组；Attribute 保留父 ID、key/value、显示状态及可为空的坐标。只有全部状态可读取且始终处于同一库、文档和标签时才返回 `scope:"current_footprint_document"`、`complete:true`。缺少 getter、ID/对象不同步、未知必要字段或超过 10000 图元/8 MiB 时返回 `complete:false`。

无孔 Pad（`hole:null`）的原生 `holeRotation` 为 `null`、`undefined` 或数值 NaN 时，以不适用状态明确返回 `null`；有限旋转值原样保留，带孔仍要求有限值。`specialPad:[]` 原样表示没有额外特殊轮廓；`pad` 或 `specialPad` 至少有一个真实非空形状。缺少 getter、空的必要焊盘/孔形状、Infinity 或字符串旋转值仍使完整读取失败。

工具仅接受可选 `timeoutMs`，Bridge 默认 60000 ms，范围 5000–120000 ms。输入示例：

```json
{"timeoutMs":60000}
```

通过 `api_invoke` 开放 21 个读取方法和 20 个写入方法：

| 模块 | 读取方法 | 写入方法 |
| --- | --- | --- |
| `eda.pcb_PrimitivePad`、`Via`、`Line`、`Arc`、`Polyline`、`String`（均使用完整模块名） | `get`、`getAll`、`getAllPrimitiveId` | `create`、`modify`、`delete` |
| `eda.pcb_PrimitiveAttribute` | `get`、`getAll`、`getAllPrimitiveId` | `modify`、`delete` |

参数使用本仓库官方 `@jlceda/pro-api-types` 0.4.15 的精确签名。Polyline 创建接收轮廓源数组，修改可用 `polygonSource`，Bridge 转换为原生 polygon；`get`、`getAll` 与写后 `after` 使用七类完整 DTO，`getAllPrimitiveId` 返回 ID 列表，长轮廓保持数组及全部元素。`identityVerified:true` 表示身份稳定，不能代替按实际 `after` 判断请求字段是否生效。删除返回已消失和仍存在的 ID。

七类 `modify` 等待一次原生 `done()` 完成，再重新读取目标图元。已完成的实际状态与请求不符时，返回 `ok:false`、`reason:"native_footprint_modify_incomplete"`、`fieldMismatches` 和实际 `after`，作为已知部分结果处理；完整回读成功时不会因此标记未知提交或隔离写入。原生调用未确认结束或写后完整回读失败仍走未知提交恢复。实机 SMD Pad 位置改到 `x:130` 已生效，但请求形状 80×60 后实际仍为 60×60；不能据此宣称焊盘尺寸修改通过。

`fieldMismatches` 逐项包含 `field`、`requested`、`actual`。Polyline 的同形闭合轮廓方向、起点及已有坐标精度规范化按等价几何比较，真实尺寸变化仍会报告差异；`after.polygonSource` 始终保留原生实际值。

最终包的实机部分修改请求将 SMD 移至 x140 并请求 80×60，返回的差异只有 `pad`：请求 `['ELLIPSE',80,60]`、实际 `['ELLIPSE',60,60]`。`hole:null`、请求 `holeRotation:0` 未产生虚假差异，没有 `commitUnknown`；下一次 x130 修改成功，七类完整回读仍为 5 控制图元且与基线 DTO 一致。

官方 `pcb_PrimitiveAttribute.create` 为内部空实现，未开放。首批之外的封装画布 API 返回 `UNSUPPORTED_FOOTPRINT_API`；库资源查询或 `lib_Footprint.openInEditor` 等全局 API 保持通用调用方式。

## 未确认写入与恢复

写入在最后一次库/文档/标签核对后立即检查 Bridge 连接、活动角色和租约，原生调用尚未开始时的切页、切换客户端或断连会阻止写入。原生超时/失联或写后身份/回读失败保留未知提交诊断，不自动重复写入。

Server 按 `bridge/task-started` 的真实执行身份记录 `requiredReadback:"footprint_state"`；旧心跳中的 PCB/工程不会作为恢复依据。恢复流程：

1. 从 `bridge_clients` 取得诊断 `requestId`，执行 `bridge_recover_client action:recover` 并提供 `confirm:true`。
2. 原生调用未确认结束或诊断要求宿主重启时，重启原 EDA，保持 Server 运行并打开同库同封装文档。
3. 使用恢复会话后的全新 Bridge `clientId` 执行 `action:readback`，提供 `recoveryId`、`clientId` 和 `confirm:true`，指定 `readbackPath:"/bridge/jlceda/footprint/read"`、`readbackPayload:{}`；按诊断提供 `hostRestartConfirmed:true`。
4. Server 验证同库同文档的七类完整状态，以及此次回读前后的标签。恢复新标签可与旧执行标签不同，回读过程中则必须稳定。

仅查询 `/context`、局部图元、错误库/文档或不完整快照不能解除该隔离。

MCP SDK 注册恢复工具时，`readbackPath` 的 enum/default 直接取自工具定义，包含封装 `/bridge/jlceda/footprint/read` 和工程 `/bridge/jlceda/project/info`；未知路径仍在 SDK 参数校验时拒绝。

## 原理图 raw 创建位号保护（#34）

`api_invoke eda.sch_PrimitiveComponent.create` 复用当前原理图页的既有位号基线与恢复流程，恢复原生创建导致的已有位号重排，并保留 BOM 扩展属性。结果返回 `designatorChanges`、`restoredDesignators`；恢复未确认时给出 `needsReview` 或未知提交诊断。完整 DeviceItem、DeviceSearchItem、SymbolItem、SymbolSearchItem 与正式库引用保留原生重载和参数，显式 `false` 参数不会被替换。

该创建的未知提交沿用 placement 恢复：`readbackPath:"/bridge/jlceda/api/invoke"`，`readbackPayload:{"apiFullName":"eda.sch_PrimitiveComponent.getAllPrimitiveId","args":[null,false]}`。Server 补充完整回读选项，核对原页全部器件 ID、位号、BOM 扩展属性及数量；不能只查询 `/context`，诊断要求时先重启原 EDA 宿主。实际重排、正式重载、BOM 保留与恢复超时已通过本地回归。

实机在原理图页 `299043c379d1c2c1` 创建 `260fdd2e8bd8b6ec`，位置 `(20,50)`、旋转 0、镜像 false、BOM/PCB false；已有 9 件器件的完整 DTO 逐项不变。本次没有触发原生位号重排，`restoredDesignators:[]`；U4/U5 重排后的恢复由本地 fixture 验证，尚未在本次实机中复现。

- Bridge 完整 build（含 TypeScript、runtime 校验与打包）及完整 lint 已通过。
- Server 全量 `npm test`、lint 和 `verify-multi-client.mjs` 已通过；协议回归覆盖中继下未知提交、执行超时和断连后的完整恢复，错误库、不完整字段及读取中换标签均保持阻断。
- 实际 stdio MCP `tools/list`、`tools/call` 在 legacy/modern 两个协议版本下核对 canonical recovery enum/default；封装和工程回读参数到达 dispatcher，未知路径仍返回参数错误。
- 原理图 raw create 回归覆盖既有位号恢复、BOM 保留、正式重载、显式 false、最后身份读取后的租约变化及恢复 RPC 未确认状态。

- 生产代码已完成两轮独立全面本地复核。发布前须以最终提交完成 CI 和关联 PR 的代码审查，再发布同版本的 Server 与 Bridge 安装包。

## 保留限制与安装

本轮支持独立封装身份、首批画布 API、完整回读及恢复。没有新增封装专用保存工具；个人封装经原生源码写回、关闭重开后保留 5 控制图元的证据已通过，此次最终 5 图元以外的修改与其他保存入口不在该证据内。PCB 封装子过孔保存后再生（#80）继续开放，尚未验证 PCB 工程库/嵌入封装来源的持久更新。

当前宿主未应用 SMD Pad 的 80×60 形状请求；Bridge 返回实际 60×60 与 `fieldMismatches`。首次 Arc 未登记的原因未确定，另一个独立 Arc 案例通过，不据此断言封装 Arc 不受支持。Attribute 修改/删除仅有本地回归，未取得实际非空样本；其他未纳入首批的图元及 EDA v4 兼容性仍未验证。

从同版本 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases/tag/v2.3.6) 安装匹配的 `jlceda-mcp-server-2.3.6.tgz` 和 `mcp-bridge-community-2.3.6.eext`，启用扩展“外部交互”并重启 EDA。是否可下载以发布页为准。运行环境需要 Node.js 20 或更高版本；本次实机版本为 EDA 3.2.181，EDA v4 未验证。
