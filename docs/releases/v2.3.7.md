# v2.3.7 发布说明

日期：2026-10-05（本地 UTC+08:00）。版本：MCP Server 与 EDA Bridge 2.3.7。本轮最终本地自动门禁、已知 EDA 3.x 网标触发路径及导线新功能实测已通过；实际发布状态以 [GitHub Release](https://github.com/hs150521/JLCEDA-MCP-Community/releases/tag/v2.3.7) 及关联 PR 为准。原 TPS552892 布局仍缺 fixture，未据此断言匿名网络合并的宿主根因已解决。

## 原理图 raw 导线创建（#22）

`api_invoke eda.sch_PrimitiveWire.create` 与 `schematic_connectivity_action action:"wire_create"` 共用当前图页接触预检和写后逐段覆盖核对。原生五参数 `line/net/color/lineWidth/lineType` 保留原顺序，支持单路径 `number[]` 和多路径 `number[][]`。导线仍须使用有效正交线段；默认不允许接触已有导线，不同已命名网络混接会在原生调用前拒绝。

raw 调用仅增加顶层可选 `allowedWireIds`，用于明确允许接触的旧导线 ID；它不是第六个原生参数，也不改变其他 API 的参数签名。其余 API 带该字段会拒绝。需要接触旧线时，先从当前页完整读取或导线预览取得真实 ID，再按预期接触范围提供该字段。例如：

```json
{
  "apiFullName": "eda.sch_PrimitiveWire.create",
  "args": [[[0, 0, 100, 0], [100, 0, 100, 100]], "MCP_TEST_NET", "#00AA00", 1, 0],
  "allowedWireIds": []
}
```

写后核验要求实际导线完整覆盖每条请求线段，且覆盖路径上存在本次新增或改变的有效导线。原生返回旧 ID 时，只有局部延伸不再足以确认整个请求；正常拆分/合并可由多个实际 ID 共同覆盖。成功结果保留 `action:"wire_create"`、`committed:true`、`commitUnknown:false`、`readbackRequired:true`、`nativeCallSettled:true`，返回 `confirmedPrimitiveIds`，并保留兼容的 `confirmedPrimitiveId`。返回的 `net` 是按原生大写规则归一后的请求名，未指定时为 `null`，不能代替实际网表。

网络接触预检和覆盖比较遵循 SDK 的大写规则，小写请求名不会因此被误报为不同网络或未知提交；raw `args` 中的原生网络参数保持原样。

成功完成覆盖核验的 raw 响应保留原生序列化 `result`，另附预检和覆盖诊断。样式参数沿官方 SDK 传入；路径覆盖核对不额外保证每个样式字段已生效。

请求路径没有完整覆盖、出现未许可的旧导线变化或无法回读时，保留 `commitUnknown:true` 和实际变化诊断，不会自动删除、重建或回滚全页图元。即使图元覆盖核验成功，仍须完整读取实际语义连接；它不能证明宿主已避免所有匿名网络合并。

标准 MCP 实机烟测使用自建原理图页：3 个普通电阻、2 个命名 NetPort、3 条基线导线，网络为 `MCP237_A`、`MCP237_B` 与独立匿名 `$1N3`。未许可的旧 A 线接触和跨 A/B 请求均被拒绝，完整 schema 快照及原生网表保持基线。授权旧 A 线后，五参数、`number[][]`、小写请求名 `mcp237_a` 的 raw 创建合并旧 ID，请求的两段均完整覆盖；另一次请求 `[100,500,100,540,200,540]` 在匿名线附近但不接触，也完整覆盖。

全部 7968 字符原生 JLCEDA 网表 JSON（含 props、pinInfoMap 和 3 个普通器件 UniqueID）严格相等；已有普通器件完整 DTO、B/匿名导线全部字段，以及端口/标识/标签保持基线。该烟测证明本轮新功能在自建场景通过，不能代替原 TPS552892 布局或断言宿主根因已解决，#22 不据此自动关闭。本机脚本 `jlc-237-wire-native.mjs` 返回 exit 0，摘要为 `jlc-237-wire-native-proof.json`。

## 未确认导线写入的恢复

raw 导线创建与受控导线创建使用相同的 `requiredReadback:"schematic_connectivity_primitives"`：

1. 从 `bridge_clients` 取得诊断 `requestId`，执行 `bridge_recover_client action:"recover"`、`confirm:true`。
2. 诊断要求宿主重启时，重启原 EDA，保持 Server 运行并打开原任务的同一原理图页。
3. 使用恢复会话后的新客户端执行 `action:"readback"`，提供 `recoveryId`、`clientId`、`confirm:true`；指定 `readbackPath:"/bridge/jlceda/schematic/read"` 和 `readbackPayload:{"includeConnectivityPrimitives":true}`，按诊断提供 `hostRestartConfirmed:true`。
4. Server 核对执行时图页身份、完整连接图元及语义网表。仅查询 `/context`、错误图页或不完整快照不能解除写入隔离。

原生调用可能仍在执行时，即时只读结果只是暂时快照，不能据此重复创建。

## raw 普通网络标签版本预检（#26）

`api_invoke eda.sch_PrimitiveAttribute.createNetLabel` 复用 `netlabel_place` 既有的 EDA 版本预检。已知 EDA major 小于 4 时，在原生调用前返回 `ok:false`、`errorCode:"EDA_VERSION_UNSUPPORTED"`、`commitStatus:"not_started"`、`nativeCallAttempted:false`。此拒绝不产生未知提交隔离。

API 索引注明该方法从 EDA v4 起提供。电源与地 NetFlag 不受该预检影响；4.x 与无法识别版本继续沿用原生调用及既有错误分类，不将它们当作已验证支持。该修补避免已知 3.x 路径进入不支持的原生方法，不能证明宿主内部故障或全部 Bridge 客户端同时失联已解决。

实机使用 EDA 3.2.181、宿主 API 0.3.15 与 2.3.7 Server、活动 Bridge。在自建原理图页调用 raw `createNetLabel`、`args:[10,20,"FSW_SET"]`，返回上述未开始及 `nativeCallAttempted:false`；`netlabel_place` 对同页 R1 的 pin1 创建普通 `FSW_SET` 也返回版本拒绝。前后 `schematic_read includeConnectivityPrimitives:true` 的完整语义与连接快照全文相等，9 个混合版本客户端 ready 且心跳正常：活动端 1 个 2.3.7，另有 6 个 2.3.6、2 个 2.3.5。切到原 2.3.6 待命客户端后完整读取仍与基线相等，再切回 2.3.7。

本轮修复 #26 的已知 3.x 触发路径。没有故意运行不受支持的原生方法来复现宿主挂死，也不把后续客户端正常扩写为宿主内部全部失联已根治；EDA v4 未实测。本机记录为 `jlc-237-netlabel-{clients-before,before,raw-rejected,semantic-rejected,after,clients-after,select-standby,standby-read,return-active}.json`，验证脚本 `jlc-237-netlabel-native.mjs` 返回 exit 0。

## 保留限制与安装

#22 原 TPS552892 匿名网络场景仍缺 fixture，宿主根因未据此断言解决；#26 已知 3.x 触发路径已被预检阻断，其他宿主内部故障不在本次通过范围。本轮不提供全页网络回滚或宿主 RPC 取消能力。PCB 自动布线 #37 沿用已有诊断和验证限制。

#80 继续开放，不属于 2.3.7 修复：独立自建 PCB 的过孔从 1 个删除并保存后为 0，冷重开又为 1；另一次显式更新自建工程库封装源后，冷重开的封装和引用 PCB 均为 Via 0，其余完整 DTO/读取部分与写源前冷基线一致。这区分了页内删除与库源持久更新；本轮没有新增封装保存工具。2.3.6 的独立封装、位号保护与历史实机证据见 [2.3.6 发布说明](v2.3.6.md)，不作为本轮新验证。
